# symmatinv

> Symbolic inverse of a symmetric matrix. The entries stay symbols; the result is a
> straight-line program you can evaluate millions of times with different numbers.
> Field-agnostic: the same program runs over float64, complex128, or exact rationals.

- n 次対称行列 A = (a_ij) の逆行列を、**要素を文字のまま** matrix inversion lemma（逆行列補題）で多段に分割して表現する Go ライブラリ。

- パラメータの組を 10^6〜10^8 通り代入して高速に逆行列を求めたいという用途向け。

- 先に数値を入れてから毎回数値的に解くのではなく、**一度だけ文字のまま解いて、
  あとは代入するだけ**にする。その際、同じ部分式を何度も計算しないよう、各段階の
  代入を最後まで持ち越さずに中間表現のまま保つ。

- 外部依存なし。標準ライブラリだけで動く。

## 用語

このライブラリで使う言葉。Go のパッケージ名・型名は英語のままなので、対応も示します。

| 日本語 | 英語（コード中の名前） | 意味 |
| --- | --- | --- |
| 命令列 | straight-line program（`tape`, `Tape`） | 分岐もループもない、代入文だけの並び。上から順に実行するだけで答えが出る |
| 式グラフ | directed acyclic graph, 有向非巡回グラフ（`dag`） | 式を木ではなくグラフで持ち、同じ部分式を1つの節点で共有した形 |
| 部分式の共有 | hash consing | 式を作るたびに「同じものが既にないか」を表で調べ、あれば作らずに使い回すこと。同じ部分式が自動的に1つにまとまる |
| 体 | field | 四則演算ができる数の集まり。実数・複素数・有理数など |
| 置き場 | slot | 計算の途中結果を入れておく配列の番地 |

`tape` は英語では straight-line program や Wengert list とも呼ばれるものの通称で、
紙テープに1行ずつ命令を打って順に読ませるところから来ています。
日本語ではこの README・コード中のコメントとも**命令列**と呼びます。

## 構成

|                    | 中身                               |
| ------------------ | -------------------------------- |
| `pkg/symmat`       | 対称行列の matrix inversion lemma 逆行列（本体、方法2） |
| `pkg/tape`         | 命令列の型・評価・JSON・Go コード生成 |
| `internal/dag`     | 式グラフ。式を組み立てて命令列にする        |
| `internal/numeric` | 部分ピボット付き LU（方法1、正しさと速さの基準）  |
| `internal/verify`  | 残差・厳密有理数による検算                    |
| `internal/inline`  | 全代入して a_ij の式にする（方法3、参考）        |
| `cmd/symmatinv`    | コマンドライン                    |

## コマンド

```bash
go build -o symmatinv ./cmd/symmatinv

symmatinv show -n 3                 # 計算手順を人が読める形で表示
symmatinv gen -n 6 -o inv6.go       # Go のソースに書き出す
symmatinv gen -n 6 -lang json       # JSON に書き出す
symmatinv verify -n 6 -exact        # 本当に逆行列になっているか検算
symmatinv plan -n 8                 # 分け方の候補と演算回数を比べる
symmatinv bench -n 6 -sets 1000000  # 方法1・2・3 の速さを比べる
```

`-plan "6=3+3[3=1+2,3=1+2]"` で分け方を指定できる。省略すると半分ずつ。
`symmatinv show -n 3` の出力はこうなる。

```
# 3 次対称行列の逆行列
# 分け方 3=1+2（matrix inversion lemma 1 段）
# 入力 6 個, 出力 6 個, 演算 29 回 (add 3, sub 5, mul 16, neg 3, recip 2)

t0 = 1 / a00
t1 = a01 * t0
...
b00 := t28
```

## 使いかた（ライブラリ）

```go
inv, err := symmat.Inverse(6)      // 6 次対称行列の逆行列の計算手順
tp := inv.Tape()

a := []float64{ /* 上三角 21 個 */ }
out := make([]float64, symmat.NumEntries(6))
scratch := tape.NewScratch[float64](tp)

tape.EvalFloat64(tp, a, scratch, out)   // これを何度でも繰り返す
```

入力も出力も**上三角を行優先で並べる**。n = 3 なら `[a00 a01 a02 a11 a12 a22]` の6個。
対称行列の逆行列もまた対称なので、出力も同じ並びになる。`symmat.Index(n, i, j)` で
(i, j) 要素の位置が引ける。

行列式は matrix inversion lemma が det A = det(A11)·det(S) を途中で持っているので、
同じ手順からただで取り出せる。

```go
tp, err := symmat.Determinant(6)   // 出力は1個
```

## 命令列

計算の結果は**命令列**として表される。命令列は分岐もループもない代入文の並びで、上から順に実行するだけで答えが出る。

```
t0 = a00 * a11
t1 = a01 * a01
t2 = t0 - t1
t3 = 1 / t2
t4 = a11 * t3
...
```

1命令がちょうど四則演算1回に対応するので、**命令数がそのまま「1回の代入にかかる演算回数」**になる。方式どうしを比べるときはこれを見る。命令は加算・減算・乗算・符号反転・逆数の5つだけ。これは体（四則演算ができる数の集まり）が備えている演算そのものなので、同じ命令列を float64 でも complex128 でも有理数でも評価できる。

```go
tp := /* ... */
out := make([]float64, 3)
tape.EvalFloat64(tp, []float64{4, 1, 2}, tape.NewScratch[float64](tp), out)
```

有理数で評価すれば丸め誤差なしに検算できる。

```go
out := make([]*big.Rat, 3)
tape.Eval(tape.RatField{}, tp, vars, tape.NewScratch[*big.Rat](tp), out)
```

複素数で使いたいときは `tape.Complex128Field{}` を渡す。このライブラリ自身は複素数を前提にしていない。

## 大きさと速さ

1回の代入にかかる演算回数（`go test ./pkg/symmat -run TestInstrCountTable -v` で出る表）。

| n | 要素数 n(n+1)/2 | 命令数 | 内訳 | 分け方 |
|---|---|---|---|---|
| 2 | 3 | 8 | mul 5, sub 1, neg 1, recip 1 | 2 |
| 3 | 6 | 29 | mul 16, add 3, sub 5, neg 3, recip 2 | 3=1+2 |
| 4 | 10 | 68 | mul 38, add 14, sub 8, neg 6, recip 2 | 4=2+2 |
| 5 | 15 | 133 | mul 72, add 33, sub 15, neg 10, recip 3 | 5=2+3 |
| 6 | 21 | 229 | mul 122, add 66, sub 22, neg 15, recip 4 | 6=3+3 |
| 8 | 36 | 536 | mul 284, add 184, sub 36, neg 28, recip 4 | 8=4+4 |
| 10 | 55 | 1041 | mul 544, add 386, sub 60, neg 45, recip 6 | 10=5+5 |

おおよそ n³ に比例して増える。n! に比例する余因子展開とは別物で、これが
「各段を代入せずに中間表現のまま保つ」ことの効き目。

命令列を組み立てるのにかかる時間（1回だけ、そのあとは何度でも代入できる）。

| n | 命令数 | 組み立て |
|---|---|---|
| 10 | 1,041 | 1 ms |
| 24 | 14,092 | 3 ms |
| 32 | 33,248 | 9 ms |
| 48 | 111,704 | 22 ms |
| 64 | 264,128 | 64 ms |

64 次でも 64 ms で終わるので、あらかじめ作って持っておく必要はない。
`symmat.Inverse` は同じ (n, 分け方) を2回求めたら2回目は即返す。

## 三方式の比較

このライブラリが答えようとしている問いは、**各段の計算を代入まで持ち越すことが
本当に得策かどうか**。`symmatinv bench` で3つの方式を比べられる。

| | やり方 |
|---|---|
| **方法1** | 先に数値を代入し、毎回数値的に（部分ピボット付き LU で）逆行列を求める |
| **方法2** | 文字のまま解き、各段の結果を中間表現のまま保つ ← このライブラリの本体 |
| **方法3** | 文字のまま解くが、各段の結果をすべて代入して a_ij だけの式にする |

方法3 は積の分配（展開）まではしない。文字どおり「代入だけ」した状態。

1組の代入にかかる演算回数。

| n | 方法1（毎回 LU） | 方法2（共有あり） | 方法3（すべて代入） | 方法3 / 方法2 |
|---|---|---|---|---|
| 3 | 45 | 29 | 321 | 11 |
| 4 | 106 | 68 | 4,238 | 62 |
| 5 | 208 | 133 | 67,078 | 504 |
| 6 | 360 | 229 | 1,665,327 | 7,272 |
| 8 | 853 | 536 | 522,878,788 | 9.8e+05 |
| 10 | 1,666 | 1,041 | 187,949,462,096 | 1.8e+08 |
| 12 | 2,880 | 1,790 | 155,020,918,387,425 | 8.7e+10 |

方法1 の数は**概算**であることに注意。方法1 は分岐（ピボット選択）とループを含む
ふつうのプログラムで命令列ではないので、命令数を正確に数えることができない。
掲げたのは浮動小数演算回数の目安 5n³/3（LU 分解の 2n³/3 と、n 本の後退代入の n³）。
桁を比べるための数と思ってほしい。

読み取れることは2つ。

- **方法2 は方法1 より演算回数でも少ない。** 対称性を使って上三角しか計算しないこと、
  同じ部分式を1つにまとめていることが効いている。方法2 が n³ 程度に収まる点は
  方法1 と変わらず、係数だけが小さい。
- **方法3 は n とともに爆発する。** 方法2 との差がそのまま「同じ部分式を何度も
  計算する無駄」の大きさ。方法3 だけは n³ ではなく、段数に対して指数的に増える。

6 次で1組を代入するのにかかる実時間（AMD Ryzen 5 5600）。

| | 時間 |
|---|---|
| 方法2（命令列を解釈実行） | 326 ns |
| 方法1（先に代入して毎回 LU） | 597 ns |
| 方法3（すべて代入） | 4.12 ms |

方法2 は、解釈実行のオーバーヘッドを抱えたままでも方法1 より速い。`gen` で Go の
ソースに書き出してコンパイルすれば、この解釈の分がなくなってさらに速くなる。

方法3 は演算回数が大きくなると現実的な時間で終わらないので、`bench` は経過時間を
表示し、`-timeout`（既定 10 分）で打ち切る。打ち切ったときは何組まで進んだかを
報告する。

## 確かめていること

- **厳密（n ≤ 6）** — 有理数を代入し、A·A⁻¹ = I が丸め誤差なしに成り立つこと
- **残差（n ≤ 8）** — 乱数を代入し、A·A⁻¹ − I が 1e-12 以下であること
- **数値 LU との一致（n ≤ 8）** — 独立に書いた部分ピボット付き LU と同じ答えになること
- **行列式（n ≤ 5）** — 余因子展開の厳密な値と一致すること
- **分け方によらないこと** — 6 次を 1+5, 2+4, 3+3, 4+2, 5+1 に分けても答えは同じで、
  変わるのは演算回数だけ（228〜229 命令）
- **方法2 と方法3 が一致すること** — 共有をやめても同じ値になること

## 設計の方針

**使われ方を仮定しない。** 入力は次数 n だけ、出力は計算手順だけ。要素 a_ij が
何であるかは知らない。実数でも複素数でも、パラメータの有理式でもよく、代入は
すべて使う側の仕事。命令列は定数を1つも持たないので、どの体の上で動かすかは
評価するときに決まる。

**上三角だけを受け渡す。** 対称行列の逆行列もまた対称なので、n² 個すべてを扱うより
演算がおよそ半分で済む。`symmat.ToFull` で n×n に広げられる。

**割り算は逆数と掛け算に分ける。** 割り算は掛け算よりずっと重いうえ、同じ分母で
複数の要素を割る場面が多い。逆数を1つの命令として持てば、部分式の共有によって
共通の分母が自動的に1回にまとまる。

**計算結果をディスクに溜めない。** 保存が効くのは計算自体が重い大きな n の場合
だけだが、上の表のとおり 64 次でも 64 ms で終わる。保存の仕組みは、それが
もたらす複雑さに見合わない。同じ結果を繰り返し使いたいときは、**Go のソースに
書き出して自分のリポジトリに置く**のが想定する使い方。

```go
tape.GenGo(w, tp, tape.GoOptions{Package: "mypkg", Func: "Inv3"})
```

書き出されるのは、こういう関数。

```go
func Inv3(v, out []float64) {
    _ = v[5]
    _ = out[5]
    t0 := v[0] * v[3]
    ...
    out[0] = t12
}
```

JSON でも書き出せる（`tape.WriteJSON` / `tape.ReadJSON`）。命令が1行に1つ並ぶので、差分が読みやすい。

**Go だけで完結させる。** 他の言語から使いたい場合は、書き出した Go のソースか
JSON を各自の都合で読み替えてもらう。
